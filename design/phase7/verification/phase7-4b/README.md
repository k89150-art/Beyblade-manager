## 實作
- 對局區標題列（核准原型）：「輪空／種子」「對手未到」直接呼叫既有 `addDirectAdvance`（沿用其確認視窗與語意）；「＋ 新增對局」開啟對話框。
- 新增對局對話框放在該比賽卡內（`data-tournament-id` 之下），欄位沿用既有屬性 `data-match-opponent`、`data-deck-select`、`data-deck-custom`。
  - 「新增對局」呼叫既有 `addMatch`：既有驗證、ID 建立、交易與草稿流程都不變。
  - 只有新對局實際存入後才關閉；取消、Esc、背景只關閉，不寫入，輸入保留為既有草稿。
  - 桌面為置中對話框（600px）；手機（≤ 700px）為全螢幕 sheet。
  - Tab 限制在對話框內；關閉後焦點回到「＋ 新增對局」。
- 3on3 重複零件提示（Q7，只提示）：
  - 依目前配置表的儲存資料，以「類別＋原始名稱」判斷零件；沿用 CX、抽包、一體式結構（「-」不是零件、CX 配置的上蓋欄不是零件、主要戰刃依 `mainStockName`）。
  - 紋章鎖可重複，只有戰神、帝王各限一個。依陀螺欄位判斷，同一配置選兩次也提示。
  - 自填、未選擇、多個配置文字相同但零件不同：顯示「未檢查重複零件」，不顯示通過；三顆都完成檢查且沒有重複才顯示「✓」。
  - 不阻擋儲存，不把配置零件寫入賽事紀錄（儲存的仍只有 `configText` 與 `source`）。
- 移除不再使用的舊卡內新增對局表單與新增回合表單函式（純渲染）。
- `tournament-panel.js` 新增 `configRowParts`、`buildConfigPartIndex`、`checkDeckDuplicates`、`LIMITED_LOCK_CHIPS`。
- 快取 `tournament.js?v=20261126-phase74b`。
- 未修改：`tournament-sync.js`、S1～S6、T1～T17、`addMatch`／`addDirectAdvance`、對局資料欄位、比賽完成狀態、收藏與配置端。
