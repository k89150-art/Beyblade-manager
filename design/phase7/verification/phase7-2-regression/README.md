# Phase 7-2 整合回歸驗證（7-2d 介面）

目的：在目前（7-2d）的介面上，逐項重跑 7-2a、7-2b、7-2c 瀏覽器驗證的每一個檢查，並補上 7-2d 複審要求的詳細面板／手機 sheet 情境。歷史驗證頁（`phase7-2a/`、`phase7-2b/`、`phase7-2c/`）與其紀錄保留不變；它們依當時「清單內嵌按鈕」的介面撰寫，不再修改。

只讀、不連 Firebase、不修改專案檔案。使用與 `phase7-2d/` 相同的真實程式切片（含 `hasUnsavedDomInteraction`、Q1 的 `resetQuickAddFormsForAccountChange`），寫入 session 替身可切換為「無 session」或「session 已失效」。

## 本輪發現並修正的問題（只在 7-2d 顯示層）

1. 手機 sheet 沒有限制 Tab 焦點：新增 `trapSheetFocus`。
2. 關閉 sheet 時原項目已不存在，焦點會落到頁面本身：`focusSelectableItem` 找不到項目時改到分頁按鈕；渲染後若焦點在已關閉或隱藏的面板內，或 sheet 剛關閉而焦點落在 `body`，改回項目或分頁按鈕。
3. 手機寬度開著 sheet 時把視窗拉寬，sheet 與遮罩留在畫面上：媒體查詢物件改存在狀態上（避免連同監聽器被回收），渲染時寬度不是手機就不保留 sheet。

## 限制

- 瀏覽器窗格隱藏時不執行畫面更新步驟，iframe 縮放後不會觸發媒體查詢 `change` 事件；此時 harness 對頁面自己的 `MediaQueryList` 送出同一事件（只驗證監聽器與渲染結果）。真實事件路徑另以 Emulator 頁面在可見的 375→1024 調整中確認。
- 寫入閘門以替身模擬；D-018 交易與衝突本身由 `tests/collection-sync.test.mjs` 等 Node 測試涵蓋，跨分頁重建由 Emulator（K4-E1）確認。
