# 04｜UI／UX 設計方向

> **決定紀錄（2026-11-23）**：使用者選定 **A 工作台**為全站骨架，賽事回合記錄採 **C 的大按鈕面板**。B（含疊層組裝器）未選定；C 只用於回合記錄。整合設計見 [prototypes/integrated-a.html](prototypes/integrated-a.html)。下方「推薦」一節為決定前的提案，保留作為紀錄。

三個方向共用 [03](03-information-architecture.md) 的頁面分類與資料流，差別在視覺語言、導覽與互動。畫面示意在 `prototypes/`（純靜態 HTML，假資料，不連 Firebase）。

共同前提：

- 保留深色／米色雙主題，結構與字級一致，只換色彩 token（D-001）。
- 手機為獨立設計：底部導覽＋底部抽屜，觸控目標至少 44px，不做桌面縮小版。
- 不加入 Tier、主觀推薦或推估勝率（D-008）。

## 方向 A：工作台（Workshop）— 專業管理工具

**一句話**：像整理工具箱，快速找到、比對、組裝，資訊密度高但層級清楚。

| 項目 | 設計 |
|---|---|
| 視覺風格 | 中性深色／米色底，系列以細色條區分（BX 藍、UX 紫、CX 橙），零件類別用小型標籤；圖示線條化；數字等寬字 |
| 導覽 | 桌面：左側窄導覽＋頂列全域搜尋與「建立配置」。手機：底部 5 項（首頁／收藏／＋組裝／賽事／更多） |
| 首頁 | 四格摘要（原裝陀螺、零件可用／持有、配置、進行中賽事）＋「需要處理」清單（衝突、未儲存資料、庫存不足的配置）＋最近配置＋快速動作 |
| 收藏與零件 | 桌面為「清單＋右側詳細面板」：可切換卡片／緊湊清單；篩選列（系列、結構、類別、可用狀態）；零件詳細顯示來源（哪顆原裝陀螺、額外庫存幾個）與「被哪些配置使用」 |
| 配置編輯 | 組裝器為右側抽屜（手機全螢幕）。頂部選結構，下方依結構出現零件槽，每槽是可搜尋的選擇器，顯示剩餘數量；底部即時檢查區（庫存、規則、重複） |
| 賽事 | 清單＋詳細頁；詳細頁是對局時間軸，每局可展開回合；「記錄一回合」用大按鈕 |
| 競賽統計 | 保留現有排行與詳細頁，套用同一套元件與色彩；手機一次一類 |
| 手機 | 底部抽屜處理所有新增／編輯；清單項目左滑出現常用動作（修改、拆解） |

**優點**
- 大量收藏時效率最高：搜尋、篩選、比對都在同一畫面。
- 最接近現有程式的 DOM 結構與資料流，最容易逐步改造、風險最低。
- 元件少而一致，長期維護與擴充容易。

**缺點**
- 視覺上較「工具」，缺乏收藏的樂趣與 BEYBLADE X 的品牌感。
- 新手第一次看到零件槽與篩選列，資訊量偏多。

**適用**：收藏量大、經常改裝、常打比賽的玩家；長期維護優先。

## 方向 B：收藏圖鑑（Collector）— 視覺化收藏平台

**一句話**：像翻收藏圖鑑，每顆陀螺、每個零件都是一張圖卡，組裝是視覺化的疊層。

| 項目 | 設計 |
|---|---|
| 視覺風格 | 大圖卡、系列主題漸層、零件以圓環疊層示意（上蓋／紋章鎖／戰刃層／固鎖／軸心由上而下）；動態轉場較多 |
| 導覽 | 頂部大分頁（圖鑑／組裝工坊／賽事／統計）；手機為底部 4 項＋浮動「組裝」按鈕 |
| 首頁 | 收藏完成度環形圖（依系列，對照官方型錄）、最近加入的陀螺大卡、「今天組什麼」快捷（只列使用者自己的配置，不做推薦） |
| 收藏與零件 | 圖卡牆，依系列分區，點開翻面顯示原裝零件；零件以「零件盒」格狀呈現，數量用堆疊點表示 |
| 配置編輯 | 視覺化疊層組裝器：左側爆炸圖逐層放入零件，右側零件盒拖放或點選；結構不同時疊層數不同（標準三層、CX 五／六層、一體式少一層） |
| 賽事 | 比賽以賽程樹／時間軸呈現，每局以三顆陀螺小圖示＋比分 |
| 競賽統計 | 排行改為圖卡條狀圖，詳細頁加頂部大標題卡 |
| 手機 | 步驟式組裝（一層一頁）；圖鑑兩欄圖卡 |

**優點**
- 最有 BEYBLADE X 的收藏感與樂趣，新手直覺。
- 疊層組裝器能直接表達「不同結構零件數不同」，規則一看就懂。

**缺點**
- 需要大量零件圖像；本專案沒有官方圖片授權，只能用抽象圖形，效果打折。
- 資訊密度低，大量收藏時要捲很多；比對、批次管理不方便。
- 動畫與圖卡改動 DOM 幅度大，與現有 `script.js` 結合的重寫量最大，回歸風險最高。

**適用**：收藏量中小、重視展示的使用者；不適合當作主要管理介面。

## 方向 C：競技儀表板（Arena）— 賽事與數據優先

**一句話**：像選手的賽前準備室，以「下一場比賽」為中心。

| 項目 | 設計 |
|---|---|
| 視覺風格 | 高對比、運動數據風格，大數字、比分板 |
| 導覽 | 首頁即儀表板；手機底部 5 項（儀表板／配置／賽事／統計／更多），收藏與零件收在「配置」內 |
| 首頁 | 進行中比賽比分板、我的配置實戰紀錄（只用使用者自己的回合結果：出場次數、回合勝負、得分方式分布）、競賽統計入口 |
| 收藏與零件 | 次要位置，以清單呈現 |
| 配置編輯 | 同方向 A 的槽位式，加上「這個配置的實戰紀錄」側欄 |
| 賽事 | 最完整：比分板式記錄回合、對局時間軸、名次計算一目了然 |
| 競賽統計 | 首頁直接顯示四類 Top 5 摘要 |
| 手機 | 記錄回合時全螢幕比分板，大按鈕 X／O／B／S |

**優點**：賽事記錄最快；個人實戰紀錄有實用價值（客觀、來自自己的資料）。

**缺點**：收藏者的主要工作被降為次要；個人實戰紀錄容易被誤讀成「推薦」，文案需嚴格限制為描述性統計；資料按配置文字快照彙整，配置改名後會分散。

**適用**：以參賽為主的玩家。

## 比較

| | A 工作台 | B 收藏圖鑑 | C 競技儀表板 |
|---|---|---|---|
| 大量收藏管理 | ◎ | △ | ○ |
| 新手易用 | ○ | ◎ | ○ |
| 配置編輯效率 | ◎ | ○ | ◎ |
| 表達組裝結構差異 | ○（槽位） | ◎（疊層） | ○ |
| 賽事記錄 | ○ | ○ | ◎ |
| 與現有程式相容、改造風險 | ◎ 低 | △ 高 | ○ 中 |
| 維護與擴充 | ◎ | △ | ○ |

## 推薦：以 A 為主架構，吸收 B 的疊層示意與 C 的賽事記錄面板

1. **主架構採 A**：最符合「完整保留功能、資料與安全機制」的前提。現有 `script.js` 綁定大量 DOM id，A 可以逐區替換外觀而不碰資料流；每階段都能單獨驗收與回退。
2. **組裝器加入 B 的「疊層示意」**：在槽位表單旁顯示簡化的疊層圖，讓使用者看出這個結構有幾層、哪一層是一體式。只用抽象圖形，不需要官方圖片。
3. **賽事採 C 的回合記錄面板**：取代 `prompt()`，在手機上大按鈕記錄回合；個人實戰紀錄列為後續功能，文案限描述性。
4. **不採 B 的圖卡牆作為主要收藏介面**，可作為收藏頁的「展示模式」切換（後續版本）。
